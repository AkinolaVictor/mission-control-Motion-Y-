**Browser Automation Paradigms (2026)**
*   **Scripted Testing Layer:** Deterministic, developer-authored, optimized for CI/CD (e.g., Playwright, Selenium).
*   **AI Agent Layer:** LLM-driven, self-healing, optimized for autonomous task completion (e.g., browser-harness, browser-use).
*   **Coding-Agent Layer:** AI writes and executes code; the browser is a disposable tool, and the resulting scripts are the persistent artifacts (e.g., Microsoft WebWright).

**Tool Comparison & Architecture**

*   **Microsoft WebWright (AI Coding Agent)**
    *   **Architecture:** Minimalist (approx. 1,500 lines). Provides LLMs with a terminal to write/execute Python/Playwright scripts, inspect logs/screenshots, and iterate.
    *   **Reasoning:** Operates at the code level rather than the pixel or coordinate level.
    *   **Performance:** Achieved 86.7% on Online-Mind2Web benchmark (GPT-5.4) and 60.1% on Odysseys benchmark (long-horizon tasks).
    *   **Integration:** Natively AI-first; supports OpenAI, Anthropic, and OpenRouter. Integrates with Claude Code via plugin marketplace.

*   **browser-harness / browser-use (Self-Healing Agent)**
    *   **Architecture:** Minimal Python core (approx. 600 lines). Connects directly to Chrome via a persistent WebSocket to the Chrome DevTools Protocol (CDP), bypassing framework abstractions.
    *   **Self-Healing Mechanism:** When a task fails, the agent dynamically edits helper files mid-execution to write new browser control tools for subsequent runs.
    *   **Integration:** Supports real Chrome sessions (including logged-in states). Uses an MCP server for integration with Claude Code.

*   **Microsoft Playwright (Scripted Testing)**
    *   **Architecture:** Uses WebSockets for persistent connections, eliminating HTTP round-trip overhead. Features `BrowserContext` for lightweight isolation (e.g., 50 workers sharing one Chromium process).
    *   **Performance (vs. Selenium):** 38% faster test suite completion; lower CPU (18.4% vs 27.6%) and memory (412MB vs 583MB) usage.
    *   **AI Integration:** Added MCP interface and Agent CLI in 2025. Acts as the underlying engine for many AI agents rather than an autonomous reasoning tool.

*   **Puppeteer (Chrome-First Automation)**
    *   **Architecture:** High-level JS API controlling Chrome/Firefox via CDP and WebDriver BiDi.
    *   **AI Integration:** Supports `chrome-devtools-mcp` and experimental WebMCP API.
    *   **Use Case:** Preferred for Chrome-specific workloads, stealth automation, and deep DevTools access.

*   **Selenium WebDriver (Legacy Enterprise)**
    *   **Position:** Used primarily in regulated enterprise environments or where legacy language bindings are required.
    *   **Architecture:** Umbrella project including WebDriver (API), IDE (recording), and Grid (distributed execution).

**Summary Table for Selection**
*   **Scripted Cross-Browser Testing:** Playwright.
*   **LLM-Driven Autonomous Tasks:** browser-harness / browser-use.
*   **AI-Generated/Maintained Scripts:** WebWright.
*   **Legacy/Regulatory Constraints:** Selenium.

**Browser Automation Tool Comparison & Architecture**

**1. Tool Paradigms**
*   **Scripted Automation (Playwright, Puppeteer, Selenium):** Human-written deterministic instructions. Optimized for repeatability, CI/CD, and regression testing.
*   **LLM-Driven Agents (browser-harness, browser-use):** LLM decides actions based on page state (CDP commands, DOM snapshots, screenshots). Optimized for autonomous task completion and novel workflows.
*   **Coding Agents (WebWright):** LLM writes and iterates on Python/Playwright scripts. The agent reasons at the code level rather than the pixel/DOM level. Optimized for reusable, composable scripts and long-horizon tasks.

**2. Technical Comparison: Selenium vs. Playwright vs. Puppeteer**
*   **Architecture:**
    *   **Selenium:** Communicates via HTTP/WebDriver; introduces per-command latency. Uses Selenium Grid for distributed execution across multi-browser/multi-OS combinations.
    *   **Playwright/Puppeteer:** WebSocket-based, eliminating per-command latency. Playwright uses `BrowserContext` for native isolation.
*   **Performance (2025 Benchmarks):**
    *   **CPU Usage:** Playwright (18.4%) vs. Selenium Grid (27.6%).
    *   **Memory Consumption:** Playwright (412 MB) vs. Selenium (583 MB).
    *   **Stability:** Playwright parallel test stability (98%) vs. Selenium (92%).
    *   **Execution Speed:** Playwright MCP (42.3s) vs. Selenium Grid (68.9s).
*   **Browser Support:**
    *   **Selenium:** Chrome, Edge, Firefox, IE, Safari.
    *   **Playwright:** Chromium, Firefox, WebKit.
    *   **Puppeteer:** Chrome, Firefox.
*   **Setup & Maintenance:** Selenium has high complexity (separate driver configuration/management). Playwright has low complexity with automatic handling.

**3. LLM Integration & Agentic Workflows**
*   **Integration Methods:**
    *   **Playwright:** Added via MCP (Model Context Protocol) interface and Agent CLI.
    *   **Puppeteer:** Added via `chrome-devtools-mcp`.
    *   **browser-harness:** Native integration; uses CDP (Chrome DevTools Protocol) directly.
    *   **WebWright:** Native; LLM acts as the driver by writing scripts.
*   **Autonomous Navigation & Self-Healing:**
    *   **Self-Healing:** `browser-harness` and `WebWright` support self-healing (agents repair their own scripts or edit helper files mid-run). Scripted tools (Playwright, Selenium) require human maintenance.
    *   **Effectiveness:** The "coding-agent" paradigm (WebWright) is demonstrably more capable for complex, multi-step tasks than "click-prediction" paradigms.
*   **Benchmarks (Online-Mind2Web):**
    *   **WebWright (GPT-5.4):** 86.7% completion rate.
    *   **WebWright (Claude Opus 4.7):** 84.7% completion rate.
    *   **Prior SOTA (Vision-based):** 44.5%.

**4. Error Handling & Security**
*   **Security Risks:** Self-healing architectures (WebWright, browser-harness) increase the attack surface because agents can edit their own code. Recommended mitigations include isolated environments, restricted file system access, and network egress controls.
*   **Stability:** Playwright is noted for lower maintenance due to built-in "auto-waits," reducing the brittleness associated with Selenium's manual wait handling.

**5. Enterprise Application**
*   **Legacy/Regulated Environments:** Selenium remains dominant in banking, healthcare, and government due to its 20-year track record and auditability.
*   **Modern Stack:** New enterprise projects almost universally select Playwright. A common "dual framework" strategy uses Playwright for new apps and Selenium for legacy suites.

**Tool Selection Criteria**

*   **Puppeteer**: Recommended for Chrome-specific features, deep DevTools access, stealth automation, anti-bot evasion, and projects with existing JavaScript/TypeScript codebases where cross-browser coverage is not required.
*   **Selenium**: Recommended for regulated industries (audited standard), legacy enterprise infrastructures, projects requiring Java, C#, or Ruby bindings, or those requiring Internet Explorer support.
