**Architectural Overview**
OpenClaw is a self-hosted, personal AI agent built on Node.js (utilizing native async capabilities) rather than Python. It employs a "gateway-centric" architecture that separates concerns into four distinct layers:

**1. The Gateway (Control Plane)**
The central local Node.js process that acts as the orchestrator. Its specific functions include:
*   **Message Routing:** Directs traffic between messaging channels and LLM providers.
*   **State Management:** Maintains conversation context and user preferences.
*   **Skill Orchestration:** Determines which "AgentSkills" to invoke based on LLM responses.
*   **Session Handling:** Manages concurrent conversations across multiple channels while isolating or sharing context.

**2. Channel Integrations (Interface Layer)**
Unlike frameworks that require custom UI development, OpenClaw uses a normalization layer to turn existing messaging platforms into control interfaces.
*   **Function:** Normalizes incoming messages from various APIs (WhatsApp, Telegram, Discord, Slack, Signal, iMessage, etc.) into a standard internal format and converts Gateway responses back into platform-specific rich text or interactive elements.
*   **Result:** A single AI assistant with shared context accessible across multiple disparate interfaces.

**3. LLM Provider Abstraction**
The architecture is model-agnostic, abstracting different AI models behind a unified interface.
*   **Supported Models:** Anthropic Claude (default/preferred), OpenAI GPT, DeepSeek, and local models.
*   **Process:** The provider layer handles prompt construction and token management, while the Gateway injects system context, memory, and skill definitions before the request reaches the model.

**4. Persistent Memory Store**
Unlike stateless chatbots, OpenClaw utilizes a local storage system for interaction history and configuration.
*   **Capabilities:** Enables cross-session context and adaptive behavior, allowing the agent to learn user routines and communication styles over time.

**Extensibility: AgentSkills and ClawHub**
*   **AgentSkills:** Self-contained modules that provide the agent with specific capabilities (e.g., shell command execution, filesystem access, Playwright-based browser automation, Home Assistant integration).
*   **ClawHub:** A skill registry that allows the agent to automatically search for and pull in new community-contributed skills on the fly, creating a dynamic capability model.

**Key Differentiators from Other Frameworks**
*   **Vs. Developer Frameworks (LangChain, CrewAI, AutoGen):** OpenClaw is a ready-to-use agent (the "product") rather than a toolkit for building agents.
*   **Vs. Cloud Assistants (Siri, Google Assistant):** It is self-hosted on user hardware, ensuring data privacy and providing deep system access (e.g., local file management and shell execution) that cloud-vendor ecosystems typically restrict.
*   **Integration Model:** It focuses on "loose, open-source" integration of models, memory, and tools rather than the vertical integration typical of enterprise AI agents.
