**Core Architectural Framework**
*   **Event-Driven Runtime:** Operates as an event-driven runtime that abstracts LLM interactions into a deterministic state machine.
*   **Three-Layer Architecture:**
    *   **Cognitive Layer:** Manages LLM inference and context window.
    *   **Execution Layer:** Handles skill sandboxing and process isolation.
    *   **Persistence Layer:** Uses SQLite or PostgreSQL for memory storage.
*   **Reactive Loop:** Unlike prompt chaining, agents subscribe to event streams, scheduled timers, or file system changes for real-time responsiveness.
*   **Unified Execution Model (v2026.3.31):** Replaced separate execution paths with a model where every operation is a node in a Directed Acyclic Graph (DAG) with standardized I/O schemas. All skills must execute through the `ClawRuntime` process to prevent privilege escalation.

**Memory Management**
*   **Memory Nodes:** Agents maintain a directed graph of memory nodes to reference previous actions and preferences without context window overflow.
*   **Memory Dreaming (v2026.4.9):** A background process using a secondary lightweight model to consolidate short-term logs into structured long-term storage (vector database) during idle periods.

**Skill and Plugin System**
*   **WebAssembly (Wasm) Sandboxing:** TypeScript-based SDK compiles skills into Wasm modules for secure execution.
*   **Declarative Manifests:** Skills use `claw.manifest.json` (and the newer `ClawManifest` spec) to cryptographically declare permissions, resource limits, and SHA-256 dependency hashes.
*   **ClawHub Registry:** Mandatory centralized distribution channel requiring signed manifests and CI pipeline vetting (static analysis and behavioral testing) to prevent malicious sideloading.
*   **Prism API:** A declarative interface allowing agents to publish capabilities as OpenAPI-compatible endpoints for multi-agent interoperability.

**Local-First & Hardware Integration**
*   **MCClaw:** A routing layer that abstracts LLM selection. It routes tasks to the optimal local backend (Ollama, llama.cpp, vLLM) based on capability tiers (fast, smart, vision) and hardware availability (e.g., native Metal support for Apple Silicon).
*   **Hybro Network Protocol:** Enables horizontal scaling and agent clustering across multiple local or remote machines.
*   **Edge Deployment:** Native support for watchOS (Apple Watch Series 9+), utilizing the Neural Engine for on-device inference with quantized 3B models.

**Security Architecture (Defense-in-Depth)**
*   **AgentWard:** Runtime enforcer monitoring system calls to block unauthorized file/network access.
*   **ClawShield:** Reverse proxy that sanitizes outbound traffic to prevent prompt injection and data exfiltration.
*   **Raypher:** eBPF-based monitoring that binds agent identities to hardware Trusted Platform Module (TPM) chips.
*   **SkillFortify:** Provides formal mathematical verification for critical skill code paths.
*   **Execution Provenance:** Every node in the DAG logs cryptographic hashes of inputs/outputs to an append-only ledger for auditability.

**Comparison with AutoGPT**
*   **Execution:** OpenClaw uses deterministic state machines/DAGs vs. AutoGPT's continuous cognitive loop (which is prone to hallucinations and infinite cycles).
*   **Memory:** OpenClaw uses persistent graphs and "Memory Dreaming" vs. AutoGPT's basic vector DB.
*   **Security:** OpenClaw employs hardware-backed, multi-layered security vs. AutoGPT's software-based sandboxing.

**Architectural Breakthroughs and Differentiators**

*   **Execution Model:**
    *   **Event-Driven Architecture:** Unlike the loop-based cognitive models used by frameworks like AutoGPT, OpenClaw utilizes an event-driven architecture.
    *   **Deterministic Execution:** Employs a unified execution model designed to ensure deterministic behavior, specifically to eliminate "infinite loops" and task hallucinations common in non-deterministic cognitive loops.
*   **Memory Management:**
    *   **Directed Graph Format:** Uses a directed graph format for its "memory dreaming" system, contrasting with the standard vector embeddings used by AutoGPT.
    *   **Resource-Aware Prioritization:** Includes a mechanism to pause background tasks (e.g., memory dreaming or optional sync operations) when system pressure exceeds 80% to prioritize critical API access and stability.
*   **Security and Plugin Architecture:**
    *   **Manifest-Driven Security:** Skills are modular TypeScript/JavaScript units requiring a `claw.manifest.json` file. This manifest declaratively defines permissions (network, file system), dependencies, and execution parameters, acting as a contract enforced by the runtime.
    *   **Cryptographic Verification:** Since update v2026.4.12, skill installation requires cryptographic signatures and verification via the ClawHub registry to prevent supply chain attacks.
    *   **Hardened Security Layers:** Incorporates specific security components named AgentWard and ClawShield for local infrastructure data protection.
*   **Deployment and Integration:**
    *   **Local-First Philosophy:** Optimized for local hardware (Apple Silicon/Metal Performance Shaders, Raspberry Pi) to avoid cloud dependency.
    *   **MCClaw:** A standardized configuration layer used to specify LLM endpoints, replacing direct API calls to optimize model management.
    *   **Modular Skill System:** Refactors discrete capabilities (e.g., web search, API calls) into individual, modular skills with defined manifests rather than prompt chains.
